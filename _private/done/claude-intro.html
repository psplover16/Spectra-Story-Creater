Claude Code 自訂功能介紹

本文件整理 Claude Code 主要的自訂與設定方式。常用功能附詳細說明與範例，較少用的僅做簡介。每個章節右側可點 ★ 加入「我的書籤」（瀏覽器本地保存）。

常用功能

1 CLAUDE.md / AGENTS.md（專案指令檔）

用途：放在專案根目錄的 markdown 檔，每次 Claude Code 啟動時會自動讀入，告訴 Claude「這個專案的規則、慣例、避免事項」。

兩種檔名差異：

  • CLAUDE.md — Claude Code 專屬
  • AGENTS.md — 跨代理通用標準（Codex、Cursor 等也讀）
  • 兩者可同時存在；Claude 會兩個都讀

位置層級：

  • 專案根目錄：所有人都套用
  • 子目錄：Claude 進入該目錄才生效
  • 使用者層級 ~/.claude/CLAUDE.md：跨所有專案套用

使用範例：

# 我的專案

## 程式風格
- 使用 TypeScript strict mode
- 縮排 2 空格、單引號

## 測試
- 以 vitest 撰寫單元測試
- 不可 mock 資料庫（會跑真實 docker container）

## 不要做
- 不要新增 dependency 沒先問我
- 不要動 `legacy/` 資料夾
提示：可用 /init 命令讓 Claude 自動分析專案產生初版 CLAUDE.md。

2 內建斜線命令

用途：在對話框輸入 / 觸發，執行系統層級操作。

命令功能
/help顯示說明與快捷鍵
/clear清除目前對話歷史（重新開始）
/model切換模型（Opus / Sonnet / Haiku）
/config開啟設定介面
/permissions管理工具權限
/cost查看本次工作階段花費
/init為當前專案自動產生 CLAUDE.md
/compact壓縮對話歷史以節省 context
/resume恢復先前的對話
/agents管理子代理
/hooks管理掛鉤
/login / /logout帳號登入登出
/mcp管理 MCP 伺服器
/statusline設定底部狀態列
使用方式：直接在對話框輸入 /，會跳出自動完成清單。

3 自訂斜線命令

用途：把常用的 prompt 範本封裝成自己的 /your-command，免去每次都打一長串。

位置：

  • 專案層級：.claude/commands/<name>.md（隨專案版控）
  • 使用者層級：~/.claude/commands/<name>.md（跨專案）

建立範例 — 翻譯命令 .claude/commands/translate-zh.md：

---
description: 把選取的文字翻譯成繁體中文
---

請把以下英文翻譯成繁體中文，保留專業術語不譯：

$ARGUMENTS

之後輸入 /translate-zh Hello world 即可觸發。

進階特性：

  • $ARGUMENTS — 接收使用者參數
  • frontmatter 可指定 model（不同命令用不同模型）
  • frontmatter 可指定 allowed-tools 限制可用工具
  • 內容可包含 bash 命令（用 ! 前綴執行）
  • 可放在子目錄建立命名空間，例如 .claude/commands/git/sync.md → /git:sync

實用範例：

---
description: 為當前 PR 寫測試
allowed-tools: Read, Edit, Write, Bash(npm test:*)
---

請為以下檔案補上 vitest 測試：
$ARGUMENTS

要求：
- 涵蓋 happy path 與錯誤情境
- 用 describe/it 分組
- 完成後跑 `npm test` 確認通過

4 settings.json 設定檔

用途：以 JSON 統一管理權限、模型、環境變數、Hooks。

三種層級（後者覆蓋前者）：

  1. ~/.claude/settings.json — 使用者全域
  2. .claude/settings.json — 專案共用（入版控）
  3. .claude/settings.local.json — 個人覆寫（不入版控）

常見設定範例：

{
  "model": "claude-opus-4-7",
  "permissions": {
    "allow": [
      "Bash(npm test:*)",
      "Bash(npm run build:*)",
      "Read(./src/**)"
    ],
    "deny": [
      "Bash(rm -rf:*)",
      "Read(./.env)"
    ]
  },
  "env": {
    "DEBUG": "true",
    "NODE_ENV": "development"
  },
  "hooks": {
    "PostToolUse": [...]
  }
}
小撇步：把敏感權限放 settings.local.json，公用規範放 settings.json 入版控。

5 權限管理（Permissions）

用途：細粒度控制 Claude 可使用哪些工具、可碰哪些檔案/網域。

規則語法：Tool(pattern)

規則意義
Bash(npm:*)允許所有 npm 開頭命令
Bash(git status)只允許這個確切命令
Read(./docs/**)允許讀取 docs 下任何層深
Edit(*.md)允許編輯 markdown 檔
WebFetch(domain:github.com)允許抓 github.com
WebFetch允許所有網域

三種設定方式：

  1. 對話中遇到工具呼叫時，按 「永遠允許」 → 自動寫入 settings.local.json
  2. 輸入 /permissions 互動式管理
  3. 手動編輯 settings.json

allow / deny / ask 三層：

{
  "permissions": {
    "allow": ["Bash(npm:*)"],
    "deny":  ["Bash(rm -rf:*)", "Read(./secrets/**)"],
    "ask":   ["Bash(git push:*)"]
  }
}
建議：把破壞性命令（rm -rf、git push --force）寫進 deny，可避免任何時刻誤觸。

6 權限模式（Permission Modes）

用途：四種模式對應不同自主程度，按 Shift + Tab 循環切換。

模式行為適用情境
default每次工具呼叫都需批准陌生任務、初次使用
acceptEdits自動允許檔案編輯（其他仍需批准）已知安全的批量改檔
plan規劃模式，僅讀取，不會改檔探索陌生專案、設計方案
bypassPermissions跳過所有權限提示（最高自主）完全信任的自動化（小心！）
注意：bypassPermissions 等於放棄安全網。建議只在隔離環境（VM、Docker、worktree）使用。

查看目前模式：在底部狀態列會顯示當前模式名稱。

7 Hooks 自動化掛鉤

用途：在 Claude 工具呼叫前後或其他事件時，自動執行你定義的 shell 命令。是「每次……就……」這類自動化的唯一正解（記憶系統做不到）。

事件類型：

  • PreToolUse — 工具呼叫前（可阻擋）
  • PostToolUse — 工具呼叫後（可後處理）
  • UserPromptSubmit — 使用者送出訊息時
  • Stop — Claude 結束回應時
  • SubagentStop — 子代理結束時
  • Notification — Claude 發送通知時

範例 1：每次編輯後自動跑 prettier（.claude/settings.json）：

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "npx prettier --write \"$CLAUDE_FILE_PATHS\""
          }
        ]
      }
    ]
  }
}

範例 2：Claude 回應結束時播音效：

{
  "hooks": {
    "Stop": [
      { "hooks": [{ "type": "command", "command": "afplay /System/Library/Sounds/Glass.aiff" }] }
    ]
  }
}

範例 3：阻擋對 .env 的讀取：

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Read",
        "hooks": [
          {
            "type": "command",
            "command": "[ \"${CLAUDE_FILE_PATHS}\" != *\".env\"* ] || (echo 'BLOCKED' && exit 2)"
          }
        ]
      }
    ]
  }
}
提示：可用 /hooks 互動式建立，會自動寫入 settings.json。

8 子代理（Subagents）

用途：把特定領域的工作交給專門子代理處理，獨立 context、可配置不同模型、可限制可用工具。主代理保持輕量。

位置：

  • 專案：.claude/agents/<name>.md
  • 使用者：~/.claude/agents/<name>.md

範例 — 程式碼審查代理 .claude/agents/code-reviewer.md：

---
name: code-reviewer
description: 資深工程師，專責審查 PR。當使用者請求 code review 時自動使用。
tools: Read, Grep, Glob, Bash(git diff:*)
model: sonnet
---

你是資深工程師，請從以下角度審查程式碼：

1. **安全性** — 注入、認證、敏感資料外洩
2. **效能** — N+1、記憶體浪費
3. **可讀性** — 命名、結構
4. **測試** — 覆蓋率、邊界條件

回報格式：分嚴重等級（critical / major / minor），每項給出檔案:行號。

呼叫方式：

  • 主代理會依 description 自動判斷何時使用
  • 使用者也可明說：「請用 code-reviewer 代理檢查這個 PR」
  • 透過 /agents 命令管理
實用價值：適合「需大量讀檔但結果只需簡短摘要」的任務（搜尋、審查、研究），可保護主代理 context。

9 記憶系統（Memory）

用途：跨對話保留使用者偏好、專案脈絡、回饋指引。Claude 自動讀寫，下次新對話會帶入。

位置：~/.claude/projects/<project-id>/memory/

四種記憶類型：

類型內容例子
user使用者背景、角色、知識「使用者是資深 Go 工程師，前端是新手」
feedback使用者對工作方式的指正「測試不可 mock 資料庫，原因：上次線上事故」
project專案進行中的脈絡「2026-03-05 起進入封版期，限制非急件 PR」
reference外部系統指引「Bug 追蹤在 Linear 的 INGEST 專案」

使用方式：

  • 明確指定：「請記住我偏好用 pnpm」
  • 自動學習：Claude 從你的回饋中自動寫入
  • 查詢：「你記得我前面說過什麼嗎？」
  • 遺忘：「請忘掉關於 X 的記憶」

檔案結構：

  • MEMORY.md — 索引（一行一條，連到實際檔）
  • user_role.md、feedback_testing.md 等 — 各別記憶
注意：記憶可能過時。Claude 會在使用前先驗證是否仍有效（例如 grep 確認檔案仍存在）。

10 模型切換（/model）

用途：選擇要用哪個 Claude 模型。不同任務適合不同模型。

模型特性適用
claude-opus-4-7最強推理複雜架構設計、難解 bug、長規劃
claude-sonnet-4-6平衡速度與能力日常開發、預設選擇
claude-haiku-4-5快速、低成本簡單 lint、格式化、明確小修改

切換方式：

  1. 輸入 /model 從清單選
  2. 或在 settings.json 設定 "model": "claude-opus-4-7"
Fast 模式：在 Opus 4.6 上可用 /fast 切換，輸出更快但仍是 Opus（不會降級為小模型）。

11 查看花費與 Token 用量

用途：知道自己用了多少 token、花了多少錢、context 還剩多少空間。Claude Code 把「花費」與「額度」分成三個層次來看。

三種情境一張表：

你想知道查詢方式
這次對話花了多少錢／用了多少 token /cost
對話歷史快滿了沒（context window） 底部狀態列百分比
Pro / Max 訂閱還剩多少額度 上 claude.ai 網站看
API 帳號用量與帳單 console.anthropic.com

1. 本次對話花費 — /cost

在對話框輸入：

/cost

會顯示：

  • 本次工作階段累計花費（USD）
  • 已用的 input / output tokens
  • 各模型分別的用量（若中途切換過）

2. Context Window 剩餘空間

Claude Code 底部狀態列會顯示目前 context 使用比例（例如 45% used）。當接近上限時可用：

  • /compact — 壓縮歷史對話、釋放 context（保留摘要）
  • /clear — 完全清空對話、重新開始
提示：context 是「對話可記住的容量」，token 是「實際算錢的單位」。兩者不同，但都會隨對話增長。

3. 訂閱方案額度（Pro / Max）

Claude Code 沒有內建命令查詢訂閱方案剩餘量。要查必須：

  1. 用瀏覽器登入 claude.ai
  2. 左下角頭像 → Settings → Usage
  3. 會看到本期已用 / 上限與重置時間

4. API 帳號用量

若用環境變數 ANTHROPIC_API_KEY 走 API，到 console.anthropic.com → Usage 查每日花費明細與圖表。

一句話記住：最常用就是 /cost，搞定本次對話 80% 的查詢需求。其餘上網看。

較少用功能

MCP（Model Context Protocol）伺服器

讓 Claude 連接外部資源/工具：Google Drive、Slack、Notion、資料庫、自家 API 等。透過 /mcp 安裝與管理。設定檔在 ~/.claude/mcp.json。

IDE 整合

VS Code、JetBrains 都有官方擴充：原生對話面板、檔案參照（@-mention）、選取程式碼即時提問、與 CLI 雙向同步。

鍵盤快速鍵自訂

編輯 ~/.claude/keybindings.json 自訂送出鍵、和弦組合（chord）、快速插入等。

狀態列（Status Line）

底部狀態列可自訂顯示內容（git 分支、token 用量、自訂腳本輸出）。透過 /statusline 配置或編輯 settings.json 的 statusLine 欄位。

輸出樣式（Output Styles）

調整 Claude 回應風格（精簡、詳盡、教學模式等）。可在不同對話模式下使用不同預設。

排程代理（Scheduled Agents / Cron）

用 /schedule 建立 cron 排程，讓代理定期執行（如每週開 PR 清理過期 feature flag、每天監控部署狀態）。也可用 /loop 在當前對話內循環執行某任務。

WebSearch / WebFetch

內建工具，用於搜尋網路或抓取特定 URL。無須額外設定，但可用 permissions 限制可訪問網域，避免意外請求。

API 金鑰與計費

/login 走 OAuth（推薦），或設定環境變數 ANTHROPIC_API_KEY 走 API。/cost 查當次工作階段花費。訂閱方案（Pro/Max）透過 OAuth 自動套用。
